# Architecture

ClipStamp is a C++20 Qt Widgets desktop application. CMake builds a domain/media library, the UI, and tests.

The application was previously named VideoTime. Project and preset JSON keep their existing `VideoTimeProject` and `VideoTimePreset` type identifiers so existing files remain compatible. Tool discovery accepts `CLIPSTAMP_FFMPEG_DIR`, with the old environment variable and saved tool paths as fallbacks.

## Data and timing

Project contains clips, a shared OverlayStyle, clock mode, time flow, output mode and destination. Each Clip stores the source path, original filesystem modification instant, frozen local start wall clock, elapsed start, and asynchronously probed media information.

Frozen wall clocks use a UTC-tagged QDateTime as a storage representation for local date/time fields, not as the original instant. This keeps the imported display unchanged when opening a project on a different timezone. Filesystem milliseconds are truncated to the displayed second. Continuous mode sums millisecond clip durations and takes its start from the first clip. Elapsed hours do not wrap at 24.

Project JSON version 1 preserves explicit start times. Opening re-probes media properties and reports missing files without replacing stored start times. QSaveFile commits project/preset files atomically. Presets contain only the shared style.

## Preview and export

QMediaPlayer feeds a QVideoSink. Preview paints QVideoFrame into the target aspect ratio, then composites the timestamp strip generated by renderStamp. FFmpeg receives the same QPainter-rendered RGBA strips over stdin, one frame per displayed second; overlay repeats the latest strip across the source video frames. Fractional timeline offsets shift the strip stream in a millisecond timebase so continuous clip boundaries and seeked samples change seconds at the correct position.

The strip has fixed geometry, transparent padding and native target pixels. Fonts, glyph layout, alpha background and outline share one renderer. Compressed YUV output and scaled preview can differ slightly at glyph edges. This design also works with FFmpeg builds without drawtext/libass.

## Jobs and errors

MediaProbe runs one ffprobe at a time, with a 30-second timeout. Import disables reordering/deletion while indices are being populated. ExportQueue takes an immutable Project snapshot, starts one FFmpeg process at a time, parses progress from stdout, and retains bounded stderr diagnostics. Timestamp writes use bounded QProcess backpressure and yield to the GUI event loop.

Separate exports are independent jobs. Merged exports normalize each segment to the first clip's dimensions/frame rate and common stereo AAC audio, then use FFmpeg concat with stream copy. Missing audio is synthesized; short audio is padded. Samples process up to five seconds from the current seek position.

A QTemporaryDir inside the destination holds intermediates. Success atomically renames the completed file within that filesystem, avoiding existing names. Failure/cancellation removes the job directory. Previously completed separate jobs remain available. A 120-second progress watchdog terminates an unresponsive FFmpeg process.

All external commands use QProcess program/argument lists with no shell. User source paths are never embedded into filtergraph strings. Concat uses generated relative segment filenames. Export image dimensions are rounded down to even numbers for H.264 yuv420p.

## Packaging

The build script downloads dependencies into .tools, runs CMake and CTest, and optionally installs a portable Windows folder. Qt deployment uses CMake's deployment API/windeployqt. FFmpeg DLLs are collected transitively with objdump into a separate tools directory so they cannot replace Qt's bundled multimedia libraries. Distribution license texts and source references accompany the package.
